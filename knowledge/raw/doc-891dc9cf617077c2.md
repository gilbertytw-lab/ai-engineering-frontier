# Harbor API Deployment Guide

## Scope

這份文件描述 `harbor-api` 從 staging 推送到 production 的最小部署流程。部署使用已建立的 release ID，不在部署步驟中重新編譯程式碼。

## Standard deployment

1. 確認 release ID 已經通過 CI，並且 image tag 與 release ID 完全相同。
2. 先部署到 staging，檢查 `/healthz` 與 `/readyz` 都回傳 HTTP 200。
3. 在 staging 執行一筆建立測試工作的請求，確認 worker 可以取到工作並完成回報。
4. production 先放量到 10%，觀察 15 分鐘的錯誤率與 queue lag。
5. 錯誤率和 queue lag 都在 release policy 的門檻內，才把流量放到 100%。

## Rollback

如果 production 錯誤率連續 5 分鐘高於 2%，停止放量並回到上一個 stable release。若這次 release 已經執行資料庫 migration，先依照 Incident Runbook 處理 migration lock，再決定是否回滾應用程式。

## Completion record

部署完成後，值班工程師要在 release record 留下 release ID、開始時間、完成時間和最後使用的 image tag。
